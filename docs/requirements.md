# EV Life Log（運転記録アプリ）要件まとめ

2026年11月13日時点。萌芽ハッカソン（本田技術研究所テーマ）。担当：伊藤。
チーム：三浦・木村（EVレンタカーアプリ担当）。PM：寺澤さん。

## 1. 目的と背景

- 1週間ふだんどおりに過ごすだけで、スマホが車での移動を自動で記録し、**「あなたの1週間の移動がEVだったら？」を自分の数字で見せる**アプリ。
- **一度ボツにした案を復活させた。**
  - ボツにした理由：結果が出るまで1週間かかると、使ってもらえないと考えた。
  - 復活させた理由：ゆいの杜店のヒアリングで、次の声をもらった。
    - 「1週間測るのは、すごくいい。早く作って」
    - 「代車を貸すときに使える」
    - 「EVに乗っていても、充電代がいくらか分からない」
  - 気づいたギャップ：チームは「すぐ結果が出ること」を重視していた。現場は「自分の数字であること」を重視していた。
- 中間報告会（11/8）では、完成イメージとボツ案を復活させた話で発表した。
- 位置づけ：シミュレーター（Web版）は「すぐ試せる入口」。EV Life Log は「自分の生活で確かめる」次の段階。どちらも販売店での相談（相談メモ）につなげる。

## 2. 対象ユーザーと記録の種類

最初の画面で、どの車で記録するかを選ぶ。

| 種類 | 計算のしかた | 見せるもの |
|---|---|---|
| 今乗っている車（ガソリン車）で記録 | 運転をEVに置き換えて計算する | 充電の不安があるか、電池の残り、費用の違い、EVだと何が変わるか |
| お店の代車・レンタカーのEVで記録 | 実際のEVの電費で計算する | 同上（点検で代車を借りたときなどに） |
| EVに乗っている人 | 記録から充電代を出す | ふだんの充電代（家・外の内訳）、ガソリン車だった場合との比較、安くする方法 |

- 想定の地域は栃木県宇都宮市周辺。想定の店舗は Honda Cars 栃木中央 ゆいの杜店。
- 検討中のEVの初期値は N-ONE e:（e:G）。軽・4人乗り、カタログ値で約295km（WLTC）、電池29.6kWh。

## 3. 機能の要件（5つの流れ）

1. **記録する**：1週間の移動を自動で記録する。画面を閉じていても位置を取る（バックグラウンド取得）。7日たったら自動で止まる。
2. **車の移動を見分ける**
   - スマホの行動認識が「車」で、時速15km以上なら車の移動とみなす。
   - 5分以上止まったら、そこで1回の運転を区切る。
   - 夜に長くいる場所を「家」と推定し、本人に確認する。
   - 家に止めていた時間を記録する。止まって待っていた時間（お迎えなど）も数える。
   - 電車との見分け：線路との重なりと、前後の徒歩で判定する。迷った移動だけ本人に確かめる。
3. **EVに置き換えて計算する**（Web版シミュレーターと同じ式を使う）
   - 選んだEVの電費×季節の係数で、1日ずつ電池の残りを計算する（電池は90%まで充電する想定。安心ラインは20%）。
   - 家に止めた時間×充電の速さで、充電できる量を計算する。
   - 通った道と行き先の近く（500m以内）の充電スポットを探す（Web版の約355件の公式データ＋OpenStreetMap）。
   - 電気代と、今の車のガソリン代を計算する。
4. **結果を見せる**
   - 判定を1行で出す（例：「充電スポットの不安なし」）。
   - 7日間の電池の残りのグラフ（冬の場合も出す）。
   - 通った道の充電スポットの地図。
   - 1週間・1か月の費用の比較（車両と充電設備の補助金、出典と確認日つき）。
   - EVを持っている人には、充電代の目安。
5. **お店につなぐ**：結果を相談メモに入れる。送るのは集計だけ（週の距離、充電の回数、費用）。チームで試した人の結果を集めて、最終報告に使う。

### EVに乗っている人向け
- **E1 設定**
  - 乗っているEVを選ぶ。
  - 家の電気料金を選ぶ。ふつうのプラン（約31円/kWh）・夜が安いプラン・単価を入れる（検針票を見る）。分からなければ「ふつうのプラン」で計算する。
  - 外で使う充電サービスを選ぶ。Honda Charge・e-Mobility Power・お店の無料充電・使わない。
- **E2 充電の記録**
  - 充電スポットに止まったら「ここで充電しましたか？（した／していない）」と聞く。
  - 払った金額は、分かれば入れる（任意）。入れた充電は、その金額で計算する。
  - 家・外での充電は、止めていた時間と走った距離から推定する。
- **E3 あなたの充電代**
  - 1週間の充電代と、月にした場合の金額、1kmあたりの金額を出す。
  - 家・外の内訳、ガソリン車だった場合との比較、「もっと安くするなら」（夜が安いプラン、家での充電を増やす）を出す。

## 4. 画面（画面イメージ v3）

タブは4つ：**記録・シミュレーション・充電マップ・相談メモ**。

| 番号 | 画面 | 主な中身 |
|---|---|---|
| 1 | はじめに | どの車で記録するか（3種類）。登録なしで始められる。位置はスマホの中だけで計算すると説明する |
| 2 | 初期設定 | 検討中のEV、今の車の燃費（分からなければそのまま）、自宅で充電できるか（できる／設備を付ければできそう／できない）。「常に許可」の説明 |
| 3 | 記録中（ホーム） | 結果が出るまであと○日、走った距離・運転の回数・止まって待った時間、途中経過、今日の運転の一覧、記録を止める |
| 4 | 1日の記録 | 地図（家・職場・充電スポット）、距離、電池の残り、家に止めていた時間と充電できる量、待っていた時間、近くの充電スポット |
| 5 | 結果 | 判定（例：充電スポットの不安なし）、走った距離・家での充電の回数・燃料代の差、詳しく見る |
| 6 | あなたの1週間で見るEVの違い | 止まって待っていた時間、ガソリンスタンドに行く回数、メンテナンス |
| 7 | 7日間の電池の残り | 日ごとのグラフ、安心ライン、冬の場合 |
| 8 | 通った道の充電スポット | よく通った道と、近くの充電スポット（Honda Charge・急速・普通） |
| 9 | 費用・補助金と相談メモ | 燃料・電気代、国と市町の補助金、自宅の充電設備、相談メモ、EVレンタカーで試す |
| E1〜E3 | EVに乗っている人向け | 上の「EVに乗っている人向け」のとおり |

- 自宅で充電できない人には、外で何回充電が必要かを正直に出す（ヒアリング：「自宅に充電設備がない人に、EVは勧めにくい」）。
- 結果は判定と3つの数字だけを先に出し、詳しい内容は下へスクロールで見せる（ヒアリング：「シンプルがいい」「精度はそこまで求めていない」）。
- シミュレーションのタブは、Web版 https://masakingduck5577-blip.github.io/ev-life-simulator/ を WebView で開く。記録の結果（1年の走行距離など）は URL のパラメータで渡す（受け取り側はこれから作る）。

## 6. 中間報告会（11/8）の意見のうち、このアプリに関係するもの

- 「一番の不安は、自分の生活で充電切れが起きないか。近所の普段使いと、遠出のときにどこで充電できるか」（shiina さん）→ 電池の残りのグラフと、通った道の充電スポットで答える。
- 「電気の契約が分からない。契約情報の写真などから確認できるとよい」→ E1 で「分からない」を選べるようにする。検針票の写真から読み取る機能を検討する。
- 「アンケートに、EVを購入した人の意見もあった方がいい」→ EVに乗っている人向けのモードが、その調査にもなる。
- 「オリジナルのIT技術はいつ出てくるのか」（テスラに乗っている方）→ 移動の自動判定と「EVだったら」の計算が独自の部分。

## 7. 守ること（プライバシー・正確さ・デザイン）

- **プライバシー**
  - 位置情報はスマホの中だけで計算する。保存はスマホの中の SQLite。
  - 外に送るのは、本人が送ると決めた集計の結果だけ（週の距離、充電の回数、費用）。位置や通った道は送らない。
  - 名前や免許証などの登録はいらない。Firebase の匿名ログインで、本人のデータだけ読み書きできる設定にする。
  - 送る前に同意の画面を出す。
- **正確さ**
  - 計算結果は正直に出す。ガソリン車の方が安い場合も、そのまま出す。
  - 補助金は、公式ページで確かめた金額だけを出す。確かめられないものは「確認中」にして計算に入れない（Web版の local_subsidy.csv と subsidy.js を使う）。
  - EVsmart など、利用規約で再配布が禁止されているデータは使わない。
  - 画面の数字には、出典と確認日を付ける。
- **デザイン**
  - 配色C：背景 #F2F5F9、パネル #FFFFFF、文字 #0F1726、紺 #0A2540、アクセント #1F6FEB。赤は Honda Charge の「H」の印（#CC0000）だけ。
  - 線のアイコン。車は Honda 公式の写真を使ってよい（チームで確認済み）。
  - デジタル庁デザインシステムに合わせる：本文16px以上、注記14px以上、コントラスト4.5:1以上、ボタン44px以上、色だけで伝えない。
  - 言葉はやさしく。例：「SOC」ではなく「電池の残り」。

## 8. 技術

- Expo（React Native）＋ Expo Router ＋ TypeScript。iPhone を優先し、12/12 までに Android（APK）も出す。
- **開発の進め方**
  - Claude Code（VS Code）で開発する。プロジェクトに CLAUDE.md を置いている。
  - まず `npx expo start --web` でブラウザで画面・入力・画面遷移を作る。同じコードを iPhone の開発用ビルドで確かめる（Web用に別のアプリは作らない）。
  - ブラウザで試せない機能（バックグラウンドの位置の記録、CoreMotion の移動判定）は、試験用データ（栃木の架空の1週間の運転のJSON）で代わりにする。
- **Web版はテストデータで動かす**（11/13 決定）
  - 位置の取得元だけを差し替える（ネイティブ：expo-location／Web：テストデータの再生）。運転の判定から先は同じコードを使う。
  - テストデータは iPhone で取るのと同じ「点の列」（時刻・緯度・経度・速さ・精度・移動の種類）にする。完成した運転の一覧は入れない。
  - シナリオ：A 通勤＋買い物・家で充電できる／B 家で充電できない／C 週末に遠出（日光・那須など）／D お迎えが多い／E EVに乗っている人。どれにも電車・バスの移動を混ぜる。
  - Web とテストデータのときは時間を早送りできる（シナリオの選択、再生の速さ、○日目へ、結果へ）。
  - テストデータのときは「テストデータで表示中」と画面に出す。
  - ネイティブでも開発用の設定からテストデータに切り替えられるようにする（最終報告会のデモ用）。
  - Web で動かない機能は .web.ts で差し替える（保存：メモリ＋localStorage、シミュレーション：iframe、通知・「常に許可」：説明のみ）。
- **使う仕組み**
  - 位置の記録：expo-location ＋ expo-task-manager。「常に許可」が必要。
  - 移動の判定：iOS の CoreMotion（ネイティブモジュールが必要）と速さ。
  - 保存：SQLite。送信：Firebase。
- **配布**：iPhone は TestFlight（チーム内のテストは審査なし。外部テストは審査に出す）。Android は APK。
- **代わりの入力（検討）**：Google マップのタイムラインのデータ（JSON）を読み込む。
- **本人の環境**：Windows・iPhone。本人は運転しないので、同乗・バス・試験用データで確かめる。
